# Calendar and availability provenance — post-final audit

The final remains consumed. No changed timing scenario, model, target or calendar-aware refit was scored in round 4. The inventory was registered in calendar-plan.json before inspection.

Eight short sessions contain 43 five-minute bars from 09:30 through 13:00 America/New_York inclusive. All last bars have non-identical OHLC values. Their volume shares range from 0.50% to 3.03%; the final-period December 24, 2025 bar accounts for 1.9443%. A zero-volume padding explanation is unsupported. Closing-auction attribution, boundary inclusivity and extended-hours filtering remain unresolved.

The [dated exchange calendar](https://ir.theice.com/press/news-details/2024/NYSE-Group-Announces-2025-2026-and-2027-Holiday-and-Early-Closings-Calendar/default.aspx) specifies a 13:00 ET equity close on December 24, 2025; eligible option hours differ. Under our frozen bar-start assumption, the 13:00 bar ends 13:05. Exactly one primary and one delayed final origin target that boundary. Primary: feature bar 12:50, cutoff 12:55, assumed availability 12:56, target 13:00–13:05, maturity 13:06. Delayed: feature bar 12:45, cutoff 12:50, assumed availability 12:56, same target/maturity. These are the assumed economic intervals, not verified first-available times. The primary matched view drops its last origin already; the delayed view does not. Earlier short sessions also entered training, so counting two final boundary origins is not a complete sensitivity assessment. Original scores are retained. This December boundary cannot directly explain the June floor events.

The history objects expose t,o,h,l,c,v, with no receipt, revision-vintage or first-available fields. Current object hashes equal the preserved extract, which verifies bytes, not original availability. R2 Last-Modified is object metadata, not a per-bar publication clock.

Repository synthetic_days/README.md (line 24) and synthetic_days/r2_sources.py attribute history/QQQ/5/{YYYY}.json to backfill_history.py. The reader's lines 112–113 explicitly identify the resolution string as MarketData.app's; this is repository attribution, not a recovered original request/entitlement record. That writer was not located by filename search in the complete local git history, local Documents search or owner-scoped GitHub code search. The separate local qqq-data-pipeline/backfill_intraday.py writes prices/qqq_intraday_YYYYMMDD.csv and tries yfinance, TwelveData and MarketData; its MarketData URL specifies 10-minute candles. It is not evidence of how these five-minute history JSON objects were produced. No writer was executed.

[Current MarketData candle documentation](https://www.marketdata.app/docs/api/stocks/candles/) defines intraday t as interval start and describes delayed rather than real-time candle access: 15 minutes for entitled nonprofessional users or one-day-old history otherwise. This is conditional evidence, not identification of the actual provider or historical entitlement. The object schema resembles that endpoint but cannot establish its origin. If that endpoint/contract applied, neither the assumed 60-second latency nor the extra-five-minute deployment delay establishes availability. No 15-minute variant was fitted after final inspection.

The deployment sensitivity changes target and refits to it. It does not isolate same-target feature staleness. Conclusions remain conditional predictive associations from a retrospective bar panel. Required resolution for future research: actual writer commit, provider request/resolution/adjustment/session settings, entitlement, ingest and first-available timestamps, original vintages and exchange-calendar boundary treatment. This provenance gap is more consequential for deployability than the small calendar-row count.
