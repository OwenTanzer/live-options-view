1.5. Full pipeline (fetch → parse → validate shape → render)

Section 1 only checks that a request reaches the server. This runs the exact production code (shared.js — the same file the live app loads) against real fetched data: parses OIranges.csv into thresholds, parses latest.json, checks both have the shape the app expects, then actually calls the app's real buildHeatmapRows() and shows the rendered rows. If any stage fails or throws, it's shown here rather than surfacing as a generic "Load failed" with no indication of which layer broke.

2. Live monitor

Polls the exact same URL pattern the live app uses (cache-busted, no-store) every 5s, against both the direct R2 path and the same-origin proxy path, and keeps a running log (persisted across reloads) with network conditions at the time of each attempt. Leave this running in the background during normal use — when "Load failed" happens again, come back here and the log will show exactly when, on which path, and what the network looked like at that moment.

3. Burst / concurrency test

Fires 6 concurrent requests on each path (12 total) at once, mimicking how the live app fires several fetches together on boot — isolates whether concurrent load (not a single request in isolation) is what triggers failures.
