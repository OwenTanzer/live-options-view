# SPY SMA(200) double-or-out paper strategy (#97)

## Strategy

`spy_sma200_double_or_out` computes a simple moving average from the latest
200 completed daily closes, including the signal day. It keeps the prior
200-close SMA and the prior close:

- bullish: prior close <= prior SMA(200) and latest close > latest SMA(200)
- bearish: prior close >= prior SMA(200) and latest close < latest SMA(200)
- equality at either comparison is no signal; only the latest close is strict
- fewer than 201 completed bars is `insufficient_history`

A bullish cross targets **200% long SPY shares**; a bearish cross targets
**cash**. The strategy never shorts, buys options or substitutes unlevered
exposure. It holds across sessions and, by explicit `overnight_hold: true`,
is exempt from the otherwise mandatory end-of-day flatten. That exemption is
opt-in and does not change existing accounts.

## Daily bars and adjustment convention

Daily bars come from the Yahoo Finance chart v8 endpoint (`interval=1d`) and
are cached under `state/sma200/SPY_daily.json`. The signal uses **adjusted
close** (`adjclose`), so splits and dividends are reflected consistently in
the moving average and buy-and-hold comparison. Only bars whose session date
is strictly before the current ET date are eligible: the current day’s bar is
never used even after the bell because a daily feed can revise it. The
strategy therefore acts on a completed prior session and executes in the next
regular session. This is an implementation convention, not a paper claim.

The strategy also pins the latest eligible bar to the **most recent completed
NYSE session** on the calendar: weekends, holidays and early-close days use the
prior regular session. A response whose latest bar is older than that expected
session is stale and produces no trade, regardless of how recently the HTTP or
cache response arrived. Missing sessions inside the 201-bar window, duplicate
dates and non-trading dates are rejected as gaps. A pending signal whose bar
is no longer the expected session is canceled rather than executed late.

The parser requires one adjustment basis. If the payload contains an adjusted
close series, every usable row must have an adjusted value; an incomplete
adjusted series is rejected rather than mixing adjusted and raw closes. If no
adjusted series is present, the rows consistently use raw close and are
labelled raw; the strategy then refuses to trade because this deployment
requires one complete adjusted-close series. Cached files record the actual
basis and a cached basis that is unknown or disagrees with its rows fails
closed. Non-finite and non-positive values are discarded.

Execution uses the existing Crassus live-quote path and the next regular
session's executable quote; it never assumes a fill at the signal close. A
missing/non-executable quote leaves the pending signal in the state file and
retries on a later cycle.

## Position and paper-account extensions

The existing Worker only allowed cash-funded share purchases and its share
allowlist omitted SPY. The smallest paper-only extension is:

1. `SPY` added to the server-side tradeable share allowlist.
2. `instrument_type` carried from `Decision` through the runner and
   `ExecutionClient` to `/api/paper-trade` (default remains option).
3. A per-bot `paper_margin_limit` (default 1, max 4). Only a flat, single-symbol
   bot share entry may borrow up to that multiple; human accounts and existing
   option accounts are unchanged. The entry is sized from **entry equity**
   (cash at entry, because the strategy only enters flat), floored to whole
   shares. Negative cash is the paper loan.
4. `paper_financing_rate` (annual, default 0) charged on the loan when the
   position is closed; the fill records `financing_cost`, `financing_days` and
   the rate. The paper engine does not model margin calls or intraday
   liquidation for this hold strategy.
5. `overnight_hold: true` bypasses the intraday flatten for this strategy only.
6. A small `strategy_state` allowlist on `/api/bot-metadata` and `/api/bots`
   so the Automated card can show the latest bar, close, SMA, target,
   position and reason. Unknown/nested fields are rejected.

The catalog entry is `active: false` and uses `CRASSUS_PW_SPY200`; no account
is created, activated or configured by this change. Previews and unrelated
bots are untouched.

## Restart and idempotency

`state/sma200/<username>.json` persists the activated-on date, last processed
bar, pending target and regime. A fresh account records the latest completed
bar as its baseline and waits for the next crossover rather than backfilling a
historical one. A signal is marked processed only after the book reflects the
target (or the target is already true), so a crash after a fill reconciles
against the server book instead of placing a second order. The existing
`ExecutionClient` request-id reservation and reconciliation remain the
authority for retries.

## Evaluation

Run:

```sh
python crassus/scripts/replay_sma200.py
python crassus/scripts/verify_sma200.py
```

The replay uses 5 bp slippage and 1 bp commission per side, 6% annual
financing on negative cash, and fixed parameters (no profitability
optimization). It executes a signal at the next session's adjusted open.
The fixture is a local Yahoo SPY daily snapshot (2006-11-07 to 2026-11-06,
5,031 bars); it is research evidence, not a live-provider guarantee. See
`scripts/fixtures/sma200_evaluation.md` for the measured table and limits.

## Integrated lifecycle

`crassus/scripts/verify_sma200_integration.py` starts a local in-memory Worker
from the real `backend/index.js` handler and a deterministic local quote
origin. It runs the actual `Runner` and `sma200` strategy through: fresh
baseline wait, bullish 2x entry, restart without duplicate, bearish exit, final
metadata readback and ledger inspection. On this Windows host only the POSIX
directory fsync is shimmed; file writes, Worker execution and ledger writes are
real. This is the required strategy → runner → Worker → ledger → restart
demonstration; no deployed account is involved.
